# Vartola — Technical and documentation audit (5 October 2026)

> **Update:** this audit describes the repository before the Testnet deployment. Items 1 and 2 of the next-tasks list (deploy and initialize the contracts, run a full facility) have since been completed; see `docs/alpha-completion-report.md`. The "NONE DEPLOYED" statements below were true at the time of the audit.

Scope: repository at commit `ed3c4ce` plus two small wording fixes made during this audit. Nothing was deployed, no Mainnet or real-money behaviour was added, Prisma and Firebase are untouched.

## 1. Fully complete (verified in code)

- SME registration, application with documents, underwriter approve/reject creating a facility and payment schedule.
- Pools, investor subscription against a virtual ledger (DEMO), release conditions (8) and activation checks (6), repayment split, early settlement (DEMO: pays the amount then closes), late/default/recovery status handling, audit log, role-separated areas.
- Risk engine: company, asset and deal scores with a risk tier. Marketplace pool rating weighs diversification, SME contribution and concentration (`lib/marketplace/risk.ts`).
- VTAED exists on Stellar Testnet (see section 12).
- Sumsub webhook signature check (HMAC-SHA256, timing-safe, rejects when the secret is missing).
- Soroban sources `wallet_registry`, `facility_contract`, `finance_math`: 10 unit tests pass.
- Public documentation routes `/pitch`, `/whitepaper`, `/how-it-works`, `/technical`, `/grant`, `/docs`, `/legal` (18 drafts, all carrying the draft banner).

## 2. Partially complete

- **Alpha mode** (`APP_MODE=ALPHA`): release, activation, repayment, settlement, status and recovery are routed to `lib/alpha/lifecycle.ts`, which writes to Prisma only after `callContract` confirms a transaction. Written but never run against deployed contracts.
- **Embedded wallets**: provider, encrypted secret and trustline code exist; only used in Alpha mode.
- **Single facility risk score**: NOT complete. Release and delivery checks and servicing status exist per facility, but no facility risk score is computed. Documented as in development.
- **Risk model versioning / input snapshot hash**: not present in the schema.
- **Document storage**: provider with SHA-256 and private object storage exists; Demo mode still writes to local disk, which is not durable on Vercel.
- **Event indexer**: reads Soroban events with a cursor and mirrors them; cannot work without contract IDs.
- **Governance**: pause and admin rotation helpers and role records; Testnet uses a single operator key.

## 3. Not connected

- **Soroban contracts are NOT DEPLOYED.** No contract ID exists in `.alpha/testnet-keys.json` or the environment.
- The deploy script `scripts/alpha/deploy-contracts.ts` is incomplete: it uploads and deploys but never calls `initialize` on either contract and never wraps VTAED as a Stellar Asset Contract. The facility contract needs the token address at `initialize`. Running it as-is would leave contracts unusable.
- `payment_distributor`, `pool_contract`, `subscription_contract`: older metadata contracts, not the Alpha money path.
- Reconciliation (Soroban vs Prisma): no job or admin view exists.
- Supplier self-service portal: no route; `Supplier` and `SupplierInvoice` models exist and are used as release beneficiary data.

## 10. Contradictions and risks found

1. Firebase journal is **not append-only in Demo mode**: `lib/stellar/record.ts` writes document id `${entityType}_${entityId}` with merge, so a later event overwrites the earlier one. Alpha mirror ids include the transaction hash and do not overwrite. Firebase failures are caught and do not affect financial state; there is no retry queue.
2. In Demo mode Prisma is the financial truth by design; in Alpha the code path is chain-first, but this is unproven until contracts are deployed. Public pages describe it as in development, which is accurate.
3. Sumsub webhook is not transactional or idempotent, maps only GREEN, RED and other to VERIFIED, REJECTED and IN_REVIEW (no SESSION_CREATED or NEEDS_REVIEW states), and the investor-only account activation depends on approval.
4. `/admin/blockchain` states configuration values are stored in plaintext; flagged honestly in the UI.
5. Legacy brand strings remain in `app/admin/setup`, the login page demo email, and the Firebase project id `assetfi-uae` (a real project name, valid). `components/marketing/futuristic-landing.tsx` is unused and says "AssetFi transforms ... into tokenized lease-to-own financing"; it is stale and not routed.
6. Old AssetFi-era files under `docs/` (architecture, implementation-plan, integration-plan, risk-engine, stellar-architecture and others) still say MVP and prototype. The README marks them historical. Not public routes.
